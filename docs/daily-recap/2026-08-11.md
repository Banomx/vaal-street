# 2026-08-11

- Boss drop labels no longer spell out "Unid" — the 20 lines that did (Sublime Vision, Watcher's Eye, Thread of Hope, Impossible Escape, Forbidden Flame/Flesh/Shako, Bound by Destiny, The Light of Meaning) now carry `unidentified: true` and show the plain item name. The prefix predates the `Unid` badge and duplicated it, worse: a label always claims the item is unidentified, while the badge only appears when the quote really came from that market. `isUnidentified` was reading the label, so the flag has to be explicit now — the "Veiled Cinderswallow Urn" labels keep their word, that is the item's name, not a restatement.
- `test-boss.mjs` fails any drop label containing "Unid" and any line with an `Unidentified …` alias that is not marked unidentified, so the prefix cannot come back by hand.

## Price sources reordered: GGG → poe.ninja → poe.watch

poe.watch was the primary listing feed with poe.ninja underneath it. That is now the other way round, everywhere: the broad price map (`RANK` in `getPriceMap`), the scarab fetch, and the astrolabe/catalyst/fossil/resonator tabs all take poe.ninja's answer and fall back to poe.watch. poe.ninja's stash item overview was already being fetched — 12 types — it was just losing every name both feeds knew.

What poe.watch still supplies, and why it is not a downgrade:

- The **unidentified markets**. poe.ninja publishes no `Unidentified X` rows at all, so those names are poe.watch's uncontested and the boss tab's unidentified-first rule is untouched. Same for anything else poe.ninja does not list; the run logs how many names poe.watch filled.
- **Its active price** is now fallback-only, and falls out of the rank change rather than needing a rule: the lookup key `wid` is only written on entries poe.watch won, so a poe.ninja-priced name has nothing to look up. Fewer beta requests per run.

Known trade-off, taken deliberately: poe.watch's exchange rows (`exchange: true`, volume-weighted completed trades) now lose to a poe.ninja *listing* on names both carry. GGG's digest covers most of that ground first, so the exposure is names GGG does not reach. If it turns out to matter, the fix is one rank in `RANK`.

## `contested` badge replaced by `poe.watch`

The old badge meant "the two feeds disagree by 1.5x or more". That was a decision aid back when poe.watch supplied the quote and `contestedFallback` might swap it for poe.ninja's. With poe.ninja winning outright the swap did nothing and the badge warned about prices that are, by observation, fine.

The badge now answers the question that is still live: **did this price come from poe.ninja?** `getPriceMap` writes `source: "poe.watch"` on fallback entries only — absence means GGG or poe.ninja, so the field costs nothing on the ~2600 normal names, and the GGG merge deletes it when it supersedes one. `sourceNote` renders a plain (non-warn) `poe.watch` badge on boss and Delve drop lines. Every unidentified drop carries it, which is correct: those markets only exist there.

`contestedFallback` and `annotateSpread` are gone, and `alt` / `spread` / `volatile` no longer go into `prices.json` at all. The comparison survives as a log line: `describeSpreads` now takes `[{ name, watch, ninja }]` and prints the widest gaps in the hourly run. Nothing acts on it — it is there so a feed that starts pricing a different item state does not go unnoticed for weeks.

Tests: `test-fetch-shapes.mjs` now mocks poe.watch too — it served none before, so nothing pinned the precedence in the first place. `test-poewatch.mjs`'s precedence assertions are inverted, and its "exchange beats listings" block moved to a direct `watchPriceMap` check, since end to end those figures no longer surface. Nothing here could be verified against the live API: poe.ninja is not on the sandbox egress allowlist, so the first real run is the CI one.

## Delve boss drop table now matches the Boss tab

The two tables answer the same question off the same resolver but looked and behaved differently: Delve's EV column was peach instead of green, and its prices were plain text — no way to correct one.

`PriceCell` (plus `NumInput`) moved out of `BossProfit.jsx` into `src/PriceCell.jsx` and both tables now render it, so the price is click-to-override in Delve too, with the same evidence tooltip and the same `↺` reset. It keeps its `bp-` class names there deliberately — the point is that the tables look the same, not that each tab styles a price its own way. Delve gained a `setPriceOverride` writing `settings.priceOverrides`, which the resolver already read and `sanitizeSettings` already persisted; nothing in the UI had ever written to it. Overrides are keyed by item name and shared with the Boss tab, so correcting a price in one corrects it in both.

CSS: `.dl-table td.ev` takes the Boss tab's green, including the "Expected per kill" total.

### New: `note` on a drop line

A short explanation that belongs on the row rather than in the source: why a line was merged, why a rate is provisional. `computeBoss` carries it through and the UI renders a hoverable ⓘ. Distinct from `unrated`, which is a status that also zeroes the line — a `note` says nothing about whether the number is usable.

### `unrated` lines, and where they ended up

Several tables list a drop the source only bounds — Imperfect Memories "<0.5%?" *(confirmation needed)*, Auspicious Ambitions "<1%", Nook's Crown "<0.5%", Keeper's Corruption nothing at all. Omitting them loses a real drop; inventing a rate is worse. So bossData gained the convention Delve already had: `chance: 0, unrated: true` with an optional `unratedNote` — listed, badged, worth nothing, still editable, because a zero is at least visibly a zero.

**All six of those lines have since been given 0.5% as a preliminary estimate**, Marcel's call, each with a `note` saying the figure is provisional and does contribute to the EV. Nothing in the dataset is `unrated` any more.

The mechanism stays, and its test moved onto a fixture rather than a real boss: pinned to a dataset line it would have stopped testing anything the moment that line got a number. It still covers the flag reaching the UI, the line being worth nothing, and — the point that is easy to get wrong — an unrated line never counting as a *missing price*. The market knowing the item and the drop table knowing the rate are different questions.

## Shipped TTK preset: Blaster

Shipped in the app rather than handed over as an importable blob, so it survives a cache clear and exists on any machine. `builtInProfiles()` in `bossProfit.js` returns it, `loadProfiles()` offers it after whatever the user has saved, and `saveProfiles()` filters built-ins out — they are code, not storage.

**Blaster**, at half the default kill time — 2x kill speed. A preset is written as its fraction of the *default*, never as a factor on another preset: a World Eater tier defined as 0.65 x Blaster came out at 3.1x because it chained onto already-rounded numbers, which reads as measured when it was chosen. (World Eater was then dropped; the rule it taught is why `builtInProfiles` takes fractions of `b.ttk` directly.)

Both are **derived from `BOSSES`**, not a pasted table. Change a default kill time and the presets follow; a copied table would have gone stale silently, the same failure mode as the hand-set prices this dataset already dropped.

`RUN_FLOOR` holds King in the Mists at 30s on *every* preset rather than being a Blaster-specific override. That run is mostly arena traversal, so damage cannot buy it back — and as a floor it means the next, faster preset cannot quietly claim an impossible run.

`PRESET_TTK` is the other exception, and a different shape: fights whose length is set by mechanics, where a preset names its own figure. Both Shapers sit there at 3:00 for Blaster — **slower** than halving would give (2:00 and 2:30), because phases, portals and dialogue do not care about damage. Keyed by preset rather than folded into `RUN_FLOOR` because these are not floors: presets can disagree about the number, and a fixed figure wins even where it is slower.

**Speed tag.** `profileSpeed()` returns the median of each boss's default time over the profile's — Blaster `2x`, an unedited profile `1x` — and it shows in the profile picker on the boss page and on each card. Median rather than mean: King in the Mists is floored and Eater rounds 22.5 → 23, and averaging lets those two drag a clean 2x into something that reads like a measurement.

`overhead` is untouched, so the five T17 maps keep their full minute of setup: a faster build does not walk to the map device any quicker. Ziggurat is therefore a 3:00 run, not 2:30.

UI: badged `preset` in amber (the green badge means "in use"), no Delete and no rename, "View times" instead of "Edit times". Editing anything while it is active forks it into `Blaster (edited)` and switches to that — every number on the Boss page is an input, and one that silently does nothing reads as a bug, while letting the edit through would redefine the preset for whoever selects it next. A saved profile that happens to be named "Blaster" — e.g. imported by hand before this shipped — is renamed on load rather than dropped.
