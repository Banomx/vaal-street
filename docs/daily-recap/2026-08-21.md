# 2026-08-21

## History loss after the repository move, and the recovery

`Initial commit` landed at 16:05Z. That push built with `DATA_MODE=reuse`, found
nothing deployed at the new Pages URL, fell through to a full fetch — and every
previous-deployment read 404'd silently, so the run rebuilt history from the
checked-in 08-19 seed alone. Two builds later the live site held
`thin(seed) + 2 points`. `banomx.github.io/scarab-ledger` and the old repository
are both gone, so the only surviving copy of the lost window was the
`github-pages` artifact downloaded from the 15:22Z run.

Lost and now recovered: 87-90 hourly points per PoE 1 family across
2026-08-19T17:25 → 2026-08-21T15:19 (671 raw points live, 2242 in the union),
every PoE 2 timeline (runes-of-aldur 2 → 25 price points, 2 → 24 exchange
snapshots; nothing was checked in at all), and the `Hardcore` league, which had
been carried forward with 08-17 data since its feed stopped and was dropped
outright by the fetch-mode league loop.

`scripts/tools/merge-pages-artifact.mjs` does the recovery: point it at extracted
Pages artifacts, oldest first, and it unions raw points, merges PoE 2 timelines
through the fetcher's own merge, takes the newest current snapshots, keeps every
league seen in any source, and rebuilds the derived curves.

Four things changed so it cannot happen again:

- PoE 2 reuse merges the local tree with the deployment instead of overwriting
  it, writes the index last, keeps a league the deployment no longer serves, and
  refuses to publish a merge that lost points.
- PoE 1 reuse overlays the deployment onto the checked-in tree rather than
  deleting it first, and fetch mode no longer wipes the output directory.
- A league that fails or disappears from the source list keeps its last snapshot
  and is marked `stale`; a run where every league is stale now fails.
- Restoring raw points rebuilds everything projected from them. The checked-in
  Allflame snapshot had an 83-point raw curve beside a one-point `rateHistory`;
  family snapshots now store `historyOrigin` so the day axis can be
  reconstructed, and `scripts/poe1/history.mjs` holds the pure logic so tools and
  tests can reach it without triggering a snapshot on import.

PoE 2 fetch failure now always exits non-zero. It used to exit 0 whenever an old
local index existed, which turned a failed snapshot into a green deploy.

## Staged publication and quality gates

Neither fetcher writes into `public/data` any more. Both generate into a staging
directory, validate it, and only promote on success — a bad run now exits
non-zero and leaves the previous deployment live. `npm run validate` runs the
same gates against the checked-in tree. Three levels: `warning` publishes,
`degraded` publishes visibly worse, `failure` does not publish. The collapse
checks compare against the previous tree instead of fixed thresholds. Each run
writes `public/data/<game>/quality.json`.

Two real bugs the gates caught on the first run: prices below 0.005c were
rounding to `0` (Rogue's Marker, Alch/Aug/Transmute, several divination cards,
31 zero points in The Catalyst's history) and PoE 2 was publishing an
`INCOMPLETE` placeholder row. Both fixed at source.

### The first code deploy failed, and why that was correct

Build #9 (`data refactor`) failed at `npm run data`. Reuse mode copies the live
deployment forward, that deployment still held the zero-rounded prices, and the
new gates rejected them — correctly, but unfixably: reuse cannot produce a
better number, only carry the one it was given, so every future code deploy
would have failed the same way.

Carried-forward data is now cleaned on the way in, by the same rule the
recovery tool uses: drop the false value, keep the observation.
`sanitizeCarried()` in `scripts/poe1/history.mjs` and `sanitizeCarriedPrices()`
in `scripts/poe2/prices.mjs`; gem history stays exempt. Reproduced against a
local fixture shaped like the live site — the run now publishes all 7 leagues
with no points lost, and logs what it cleaned.

Two more defects fell out of chasing it:

- `validate.mjs` ignored a directory passed as its first argument (`indexOf`
  returning -1 made the arg-skip index 0), so `node scripts/poe1/validate.mjs
  <dir>` silently validated the default tree and reported it clean.
- `quality.json` checks are `{level, code}`, but the browser read `{state, id}`,
  so no degraded or failed check could ever reach the banner. The test now
  builds its fixture from a real `QualityReport` instead of a hand-written
  object.

## Sources, metadata and identity

Every fetch records where its numbers came from — URL, fetch time,
ETag/Last-Modified, content hash — in a per-league `sources.json`. RePoE
publishes no version, so the content hash is the only way to notice its
dictionary changed. PoE 1 and PoE 2 endpoint choices moved into
`endpoints.mjs` per game, each entry naming its consumer or the reason it is
omitted; that turned up four documented PoE 2 exchange types we were never
requesting (`UncutGems`, `Essences`, `Idols`, `Runes`), so everything in them
was unpriced or pushed onto a listing feed.

Item identity is now explicit: a GGG Metadata path beats a source-scoped numeric
id, which beats a name match (recorded as low confidence, never used as rename
evidence). Family classification prefers GGG tags and item class over name
regexes, and the confidence tier is reported rather than hidden.

## Browser data contract

`src/shared/data/snapshot.js` decides whether a downloaded file may be rendered:
`ready` / `missing` / `offline` / `corrupt` / `incompatible`, folded into one
verdict with freshness and `quality.json` and shown as a banner. Both apps now
address files through the `files` map their index publishes.

Two behaviours are gone. PoE 2 no longer fabricates a one-point history from the
current snapshot — a flat line and a 0% move is a claim about the market — and
shows an explicit "current snapshot only" state instead. And a production build
reads snapshots only: the poe.ninja API and the sample dataset now need
`?data=live` / `?data=demo`, so a broken deployment can never be quietly
answered with invented prices.

## Naming

`scarab-ledger` is gone from the package name, the User-Agent strings (one
shared `USER_AGENT` in `scripts/shared/dataset.mjs`), the vite proxy headers and
the README.

## PoE 2 Exchange table

The bottom market turnover filter now applies to both overall item turnover and
each route's limiting leg. Cheapest buy, best sell, eligible route count,
difference, and sorting are recomputed from surviving routes. Buy and sell
cells show their limiting route turnover so an unchanged qualifying winner is
verifiable. Tests cover a stricter floor replacing the previous winner.

Clicking a bottom market row now reveals that market in the top route finder and
syncs the shared browser to its category instead of letting the previous filter
override the selection.

The hourly market fetch now starts at ten minutes past the hour. The Currency
Exchange source strip shows the official GGG market hour and shared currency
ratios, without a poe.ninja comparison timestamp.

PoE 2 market categories now prioritize specific GGG item tags over broad
classes, fixing refined catalysts and Verisium. Breach, Abyss, Ritual, Omens,
Vaal, and Incursion no longer share league subcategories. Exchange chart ticks
use compact numeric times without locale suffixes. The largest route differences
panel now ranks up to eight items after applying the selected hourly route floor.

## Currency and controls

Market source strips now include the useful conversion chain: Chaos to Divine
and Divine to Mirror for PoE 1, plus Exalted to Chaos/Divine for PoE 2. PoE 2
also has a Chaos display mode backed by same-hour rates in boss values, price
history, and exchange charts. Its boss list defaults to Gross EV per kill.

PoE 1's shared sort and price-change controls use the shell's segmented styles
again. Overview, Boss profit, and Delve now use the same source-strip component
and spacing as the other tabs.

## PoE 2 tablets and boss drops

Boss independent drops now use item-family tables. The Aberration's Emergent
runes are separate from its two Lineage Supports; mixed rune/support, key, and
Vaal-currency tables on other bosses were split in the same pass. Guaranteed
drop pools and rates were not changed.

Popular farms now groups tablets into league-mechanic cards with a stored price
graph and Divine-adjusted movement. The Normal precursor tablet is the baseline;
Magic, Rare, and unique tablet prices cannot silently replace it. Unique tablets
remain listed on the card as market context. Cards now rank by baseline value
by default, with movement/name sorting available. Summary tiles, source and
liquidity badges, stored-point counts, and unique-to-baseline multiples make
the league cards easier to evaluate. Unique tablets are now full market tiles
with current price, source/liquidity,
absolute difference, baseline multiple, and a relative-value bar.

The deployed feed audit confirmed current prices are poe.ninja Normal-tablet
quotes. The large chart jumps came from older history using the cheapest rarity,
not from the market. A versioned migration now clears only those incompatible
tablet points and restarts their graphs from the honest Normal baseline.

## PoE 1 market movement

Scarab and Popular farms movement now comes from the latest stored snapshot for
both active and finished leagues. Finished leagues no longer inherit flat 0%
placeholders from their fallback price feed. PoE 1 price charts also use the
same line-draw animation as PoE 2, including overlays and Divine-rate lines.
Market-chart animations in both games finish in one second instead of the
default 1.5 seconds.
