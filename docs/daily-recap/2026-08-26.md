## Data reliability follow-up

Closed the remaining gaps from the source-metadata audit without running a live
fetch or changing `public/data`.

- Removed the workflow and fetcher history-reset path, including the unused
  `deploy.yml.fixed` copy. Recovery is merge-only.
- Interrupted stage promotion now restores the newest `.previous-*` tree before
  cleaning scratch directories.
- PoE 1 records poe.ninja and poe.watch requests beside GGG/RePoE provenance;
  PoE 2 now carries the GGG/RePoE records that were lost at the league boundary.
- Cross-source quote selection uses source trust, freshness, liquidity, spread
  and item-state compatibility. Large name-only disagreements cannot let a
  lower-trust source replace a better-identified quote.
- New snapshots use schema 2. Version 1 stays readable. Schema 2 publication
  requires provenance for selected sources and validates metadata accounting,
  ambiguity/name fallbacks, rejection spikes and coverage regressions.
- Code-only deployments can reuse early schema 1 `sources.json` manifests;
  request-level provenance becomes mandatory only at the schema 2 boundary.
- File-contract tests now import each app's supported schema versions instead
  of hard-coding version 1, so mixed v1/v2 migration datasets are tested the
  same way they are read in production.
- Restored the project map and data-contract rules in `AGENTS.md`; deploy CI now
  runs the complete tests and explicit dataset validation before building.

Fixture-backed publication and resolver tests cover the new behaviour. No live
API call or history rewrite was part of this change.
