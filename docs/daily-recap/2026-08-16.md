# 2026-08-16

## Strat Watcher graph

Saved strategies now have the same league graph the other tabs have. Clicking a
saved setup opens a `PriceChart` under it showing what the whole setup cost over
time; clicking one of its item icons overlays that single item on the line.
Clicking the same icon again drops the overlay, clicking the title closes the
graph.

Files: `src/stratHistory.js` (new, combining maths, no React),
`scripts/test-farm-strategy.mjs` (extended), `src/App.jsx` (state, history
fetch, card markup, CSS), plus a comment fix in `PriceChart.jsx`.

### Decisions worth keeping

- **The window is the overlap, not the union.** A strategy is up to six series
  that do not start on the same day. Extending a short one with its current
  price would draw a plateau that never traded, and dropping a member partway
  back makes the total look like a crash. So: latest first day → earliest last
  day, and the note under the graph says when it was clipped.
  Consequence to live with — one item with a single snapshot pins the window to
  one day, and the chart then says it has nothing to draw yet. That is accurate;
  the setup cost genuinely isn't known before that.
- **Missing history is named, never filled in.** An item with no series at all
  is listed under the graph and left out of the sum.
- **Nearest sample inside the window.** Sources are sampled hourly at slightly
  different minutes, so exact-day matching alone leaves the total full of holes.
- **The Astrolabe joins only when the day axes agree.** `scarabs.json` and
  `astrolabes.json` are day-aligned independently, so day 3 in one is not
  necessarily day 3 in the other. Mismatch → scarabs-only line plus a one-line
  reason. In live (non-static) mode there is no category history at all, and it
  says that instead.
- **Duplicate scarabs count twice on the chart**, the same way
  `computeFarmStrategy` prices them twice.

### Other

History fetching now keys off "whatever is on screen" (open mechanic panel ∪
open strategy) instead of the open group alone, through the same effect — a
strategy reusing an already-charted scarab costs no extra request.

The saved-card title became a button, so a dead
`.st-strat-saved > button { grid-column: 2 }` rule in the 480px block had to go
(it would have thrown the title into the actions column); `.st-strat-actions`
already claims that cell.

The saved cards also never lined up with each other: each card is its own grid
and three of its five tracks were content-sized, so a two-scarab strat and a
six-scarab one put the cost and the move at different x — and the leftover fr

columns run straight down the list.

Checked against a synthetic snapshot in `public/data/test-league/` (scarabs +
astrolabes + both history files, one scarab deliberately starting at day 9) at
1280px and 430px, then deleted — `public/data` is committed and stray test data
would ship.

## Hourly data for every family

Building that graph turned up why the Astrolabe curve only held a day and a
half: category history has no backfill, it only grows one point per run, the
workflow ran every 4 hours, and the accumulated file lives *only in the last
deployment*. So any run that priced nothing for astrolabes shipped without the
file and the next run restarted the curve from one point. The scarab curve hid
the same fragility behind poe.ninja's backfill.

Files: `scripts/fetch-data.mjs` (most of it), `scripts/test-history.mjs` (new),
`deploy.yml.fixed`, `src/App.jsx` (two fetch/label lines), docs.

### Decisions worth keeping

- **Hourly, at :07.** GGG publishes one digest per completed hour and the
  fetcher already asked for the last completed one — the 4-hourly cron was
  throwing away three quarters of the feed. Off :00 because the digest needs a
  moment on the CDN and because that minute is when every Actions cron fires.
- **Backfill fetched once per league, stored with absolute timestamps.**
  poe.ninja's `itemhistory` is ~90 requests and hourly runs would make that
  2,160/day for a curve that doesn't change. It answers in `daysAgo`, which is
  only true at the moment of the request, so storing it raw would slide the
  whole curve a day off the axis every day it was reused.
- **One origin per league.** League start when it's known and plausible,
  otherwise the earliest point held. Every family and the rate line hang off
  it. Before this each family anchored day 0 at its own first snapshot, so day
  3 meant a different moment on each tab — which is exactly why Strat Watcher
  had to exclude the Astrolabe. It no longer does.
  Same bug inside the ninja backfill: day 0 was read per item as "this item's
  oldest point", so a scarab listed since day 40 sat on top of one listed since
  day 0 and the set total summed two different weeks.
- **Stitch, don't choose.** Backfill for the days before our snapshots start,
  hourly accumulation from there, ours winning the overlap — the same 10-minute
  bucketing `buildRateHistory` already used for the divine rate. The scarab
  chart previously ignored self-history entirely whenever ninja answered, so
  hourly detail never reached it.
- **Carry forward instead of writing nothing.** A family that prices nothing,
  or throws, keeps its deployed files; so does a league that has rolled over to
  previous. This is the actual fix for the lost history — everything else is
  frequency and resolution.
- **72h at full resolution, one point per UTC day before that, ~8 months
  retention.** The change badges read 1h-48h straight off these points, so that
  window can't be thinned; 8 months keeps last league readable end to end. A
  league costs under 200 points, so the cap (1,200) is headroom, not the shaper.
- **A change window won't resolve against a point much older than itself.**
  `refFor` had no upper bound, so with 4-hourly data the "1h" badge was really
  showing a 4h move. After a missed run the badge now goes blank instead.

### File layout

Scarabs used to write `history.json` / `selfhistory.json` while categories used
`<key>-` prefixes. All five families now follow one rule —
`<key>.json`, `<key>-selfhistory.json`, `<key>-backfill.json`,
`<key>-history.json`. The old two names are read once so the accumulated curve
migrates instead of restarting, and both stay in `LEAGUE_FILES` until a fetch
run has done that migration (a code push in between would otherwise delete
them). Safe to drop those two entries after a deploy or two.

## Gem levelling tab was never wired into the shell

`src/Gems.jsx` and `src/gems.js` were in the repo, the snapshot writes
`gems.json` and `gems-selfhistory.json`, and Overview has a gem desk that calls
`onOpenTab("gems")` — but `App.jsx` had no import, no nav button, no mount and
no `.gm-*` CSS. So the tab was unreachable, and the Overview gem signal set a
tab that rendered nothing. Not lost in a recent edit: no version of `App.jsx`
in the repo has ever referenced it, and the built bundle in `dist/` predates
the gem work, so the mount half of that change never landed on main.

Added the import, a **Gem levelling** nav entry between Boss profit and Delve,
the mount with the same props Delve takes, and the stylesheet. The CSS is
written against Delve's values — same toolbar, table, expandable row and
assumptions panel — because the three tabs are meant to read as one site.

One real bug found while styling: `.gm-field > span` also matched `NumInput`'s
wrapper span, so the unit suffixes rendered as "LISTINGS" and "M/MIN". Scoped
to `:first-child`.

Both routes are badged now, not just `vaal it` — a row with no badge could mean
either "sell it" or "the route filter is not on best". `level & sell` is the
quieter green of the two: the vaal route is the one that costs an orb and can
brick, so it keeps the louder colour.

## Scarab tab listed scarabs that no longer drop

Breach showed nine rows: the five current ones plus Breach Scarab, of
Splintering, of Lordship and of Snares. They are not a bug in the data — the
feeds price every scarab that still *trades*, and the retired sets still sit in
stashes in the permanent leagues. But it made the mechanic look half again as
big as it is and inflated its set total by a third.

Rebuilt the catalogue against poedb's Scarab item class (118 items, generated
from the game files; poewiki still lists the old Abyss scarabs and no Trarthan
ones, so it is a league or so behind). Moved it out of `App.jsx` into
`src/scarabs.js` with `groupForName`, and put the assertions in
`scripts/test-catalogue.mjs`.

Also stale in the old list: **Abyss missed its 3.29 rework** ("of Edifice" and
"of Profound Depth" replaced by "of Crystals" and "of the Consort" — poe.ninja
prices both new ones in Allflame, so it is a real rework and not poedb showing
something unreleased), **Trarthan was missing entirely** (4 scarabs), and so
were Scarab of the Commander and Scarab of Evolution.

### Decisions worth keeping

- **A rule, not a list of retired names.** First attempt was a `DROP_DISABLED`
  set, which only caught the retirements I happened to know — it missed all
  four of the Breach ones actually on screen. Now: anything the feeds price
  that is not in the poedb catalogue no longer drops.
- **Filtered in the UI, not in the fetch path.** The snapshot still prices
  everything and stays list-free, which is the property that lets a new scarab
  appear with no code change. Mechanics, movers and Popular farms read the
  current catalogue. `items` stays whole for saved strategies and price
  lookups — someone with a retired scarab in a strategy still gets its price.
- **No toggle.** First cut had a `Legacy (n)` checkbox and a `no longer drops`
  tag; a scarab that cannot drop is not a farming decision, so the option was
  just a switch nobody would touch. Retired scarabs are simply out of the
  browse views. The cost is that a scarab GGG adds mid-league stays out until
  the catalogue is updated — the drift report already names it on the run it
  appears.
