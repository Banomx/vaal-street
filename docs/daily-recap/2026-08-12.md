# 2026-08-12

## Gem levelling tab

New tab: buy a gem at level 1, level it to its cap, sell it or vaal it. Ranks
every gem poe.ninja prices by the profit on one cycle, with a sparkline column
and a per-row panel (profit chart left, corruption outcome table right).

Files: `src/gems.js` (maths, no React), `src/Gems.jsx`, `scripts/test-gems.mjs`
(28 assertions), plus `Sparkline` in `PriceChart.jsx`, a `SkillGem` branch in
`scripts/fetch-data.mjs`, and the nav/mount/CSS in `App.jsx`.

### Decisions worth keeping

- **No gem names anywhere.** Level and quality caps come from the uncorrupted
  variants poe.ninja lists, so 20/20, 5/0 and 3/20 all fall out of the data and
  an Awakened gem needs no special case. A gem listed only at level 1 is not a
  row.
- **Corruption weights are the published ones** — 1/4 each, level and quality
  split 50/50 inside their quarter, quality 1–10 uniform capped at 23. The one
  genuinely unsettled bit is a gem with no Vaal version: the wiki says "each
  possible effect" (→ 1/3 each, +1 level at 1/6) *and* says +1 level is 1/8.
  Default keeps 1/8 (the quarter does nothing); the strict reading is a radio in
  Assumptions rather than a silent choice.
- **Input is the cheaper of the two routes**, listed 1/20 vs 1/0 + 20 GCP, and
  the row says which won. On Awakened gems quality is only experience, so there
  is one route and it is not shown twice.
- **Unlisted outcomes are substituted, not zeroed.** poe.ninja has no market for
  a corrupted 20/14; zeroing the quality-down band would cut an eighth off every
  EV. `quoteVariant` walks down, then up, then across corruption state, and the
  row is badged `approx` — but only when the substitution is carrying ≥10% of
  the EV, otherwise the badge is on every gem and means nothing.
- **Listing count is the thinnest market carrying ≥10% of the EV**, plus the
  input. Using the worst market on the route just reported the level 19 nobody
  buys. Threshold is editable (default 5), rows badge `thin`, and **the hide
  filter is on by default** — a profit resting on four listings is the common
  case here, so leaving them in makes the whole list read as free money.
- **Alternate quality excluded** (can't Gemcutter a Superior into a Divergent —
  different trade, different input). Vaal gems are outcomes, never rows.

### Labelling pass

First cut used tool shorthand — "Buy at 1", "Sell at cap", "Corrupt EV" — which
reads as jargon and, worse, "Corrupt EV" gets misread as the +1 result rather
than the chance-weighted average of every outcome. Now:

- Two-line headers: what the column is, then which gem state it refers to
  (`Buy it at / level 1`, `Sell it levelled / no corruption`).
- **`Vaal: +1 level` is its own column**, showing what the 1-in-8 jackpot sells
  for, beside `Vaal: average`. Each cell names the tier it means — `21/20
  corrupted` for a normal gem, `4/20 corrupted` for Empower/Enhance/Enlighten,
  `level 6 corrupted` for Awakened, since "6/0" is not how anyone refers to
  those. `tierLabel()` in `gems.js` owns that.
- One legend line above the table spelling out the cycle and the difference
  between the two vaal columns, so the Assumptions panel is optional reading.
- Panel outcome table is now "You end up with / Chance / Sells for / Listed /
  Adds to average", each row naming the resulting gem and the rule that made it
  ("21/20 corrupted" + "+1 level"), totalling to "Vaal average".
- Second pass on the two vaal columns: `If you hit +1 level` / `1 roll in 8`
  and `Worth after vaaling` / `average of every outcome`. The sub-line under
  the average names its comparison rather than restating the header — "88% roll
  below level 5", i.e. below the gem you already had.

### Overview: gem desk, and the briefing actually rotates

Gem levelling is now a sixth desk in both briefing panels, ranked by profit per
hour off the same `computeGems` and the same saved settings the tab uses. It
drops thin markets regardless of the tab's filter — a headline resting on three
listings is worse than no headline.

The feature card also rotates now. It sat on Popular farms permanently while
only the small print underneath changed, because `selectedRising` defaulted to
`"farms"` and nothing moved it. `rotateDesks(count, tick)` in
`overviewTrends.js` steps the highlight one desk per tick and advances the
entries only once a full lap is done, so every desk shows its #1 before any
shows its #2. Selection state starts null (follow the rotation); clicking pins,
clicking the pinned one unpins, and a pinned card is badged and outlined so it
does not read as stuck.

### Fixed: a code push wiped the gem data

`mirrorExisting()` (reuse mode, what a push to `main` runs) copies the live
deployment's data forward file by file from a hardcoded `LEAGUE_FILES`. The
three gem files were not in it, so every code push deleted `gems.json` — tab
empty until the next scheduled run — and `gems-selfhistory.json`, restarting
the profit curve from zero each time.

`LEAGUE_FILES` now derives the per-category names from `src/categories.js`
instead of repeating them (the same trap was one forgotten line away for any
new family), names the gem files explicitly, and picks up `catalogue.json`,
which was also being dropped. `test-fetch-shapes.mjs` now diffs the files a run
actually writes against the list, so this cannot come back quietly.

### The history trade-off

~800 gems × every variant × a league of hourly points is megabytes. So
`gems-selfhistory.json` stores one number per gem per run — the profit under
default assumptions — and the browser recomputes today's figures live from
`gems.json`. Overrides and the Vaal-slot setting move the rows, not the curve;
the panel says so in words. Points stay hourly for 48h then collapse to one per
UTC day, capped at 400 (`thinPoints`).
