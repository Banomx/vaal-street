## Two bugs the deployed site showed, both from yesterday's changes

**The gem tab was empty and said the data had not been generated yet.** It had.
`gems.json` holds `gems`; the tab asked the snapshot reader for `items`, so
every valid file was refused as unreadable and the panel fell back to its
"appears after the next refresh" empty state. No error anywhere — the page
simply told people to wait for data that was already on disk.

Each generated file's required fields now live in one place per game —
`POE1_FILE_CONTRACTS` / `POE2_FILE_CONTRACTS` in `config.js` — and every panel
reads from there instead of restating the contract from memory.
`scripts/tests/shared/test-contracts.mjs` checks those constants against
`public/data`, so a rename on either side fails a test rather than emptying a
tab in production. It also checks that every league's `files` manifest names
files that exist. `src/shared/data/paths.js` tolerates a missing
`import.meta.env` so the config is importable from node, which is what makes
the test read the app's own constants rather than a copy of them.

**`Hardcore` was advertised without a files map, and not marked stale.** The
"no usable scarab data" branch — the league is still in the source list but the
feed returned no rows — carried the deployed files forward and then pushed an
index entry with neither `files` nor `stale: true`. So the browser guessed
filenames (the banner on the site) and presented an old snapshot as current.
It now behaves like every other league that produced nothing that hour.

Both fixes are in; the banner clears on the next run of either mode, and the
gem tab works as soon as the new build deploys.

## Popular farms now prices the return, not just the tablet

The PoE 2 tab was a tablet price browser: 16 tablet markets, 8 cards, and every
number on the page an entry cost. It never said what a mechanic gives back.

Everything needed for the other half was already in the snapshot and unused —
1106 priced markets, 1107 hourly history series, and GGG `volume1H`, which is
real cleared trade volume. Each mechanic's output pool is identifiable from
metadata: Breach 28 markets, Ritual 38, Delirium 27, Abyss 15, Expedition 19,
Vaal 19.

Each card now charts entry cost against a fixed-weight index of that mechanic's
markets, both rebased, plus cleared trade per hour, pool movers, concentration,
and curated chase uniques. `mechanics.js` owns membership, `farmIndex.js` owns
the index.

Three things the model refuses to do, because the data does not support them:

- **No drop rates.** Weights come from traded supply. That is a market
  measurement standing in for production frequency, and it is labelled as one.
- **No EV per map.** The tower rules give relative exposure between mechanics,
  not absolute yield, so the return is an index rebased to 100 and never a
  number of Exalted per map.
- **No pretending a tablet cost is real.** Every source quotes precursor tablets
  at Normal only, so the entry cost is a floor. Tablets roll 2 prefix and
  2 suffix and nothing prices a rolled one.

Three problems only showed up once the page was actually open:

- **Expedition was missing entirely.** It clears more than any other mechanic
  (2.2M ex/h) but Runes of Aldur prices no Expedition Tablet, and the card list
  was keyed off tablet families. A mechanic now gets a card if either half
  exists; a missing tablet reads as an unknown entry cost. This also means
  Standard, which has no tablets at all, went from an empty tab to five cards.
- **Spread was nonsense at large moves.** Subtracting percentages turned a
  tablet up 486% against a basket down 6% into "-492%". It is a ratio now.
- Unique tablets cheaper than their baseline all displayed "0× baseline".

One imprecision is named on the card rather than hidden: GGG files every Omen
under Ritual, including Abyss-themed Omens that also drop from Abyss, and no
source splits that supply.

`scripts/tests/poe2/test-farms.mjs` covers membership, the source-vocabulary
trap, weighting, the overlap window and the spread ratio. Wired into
`test:poe2`. Read-only on `public/data/`.

## Expedition is priced by its logbook

Leaving Expedition at "Entry cost unknown" was honest but incomplete — the
mechanic has a purchasable entry, it is just not a tablet. A tablet covers
roughly ten maps in its tower radius and a logbook grants roughly ten maps of
Expedition, so the two quotes buy the same block of access and compare directly.
No per-map divisor is applied; "around ten" is too soft to put into a displayed
absolute number.

`ENTRY_SOURCES` in `mechanics.js` declares it, matched on the
`expedition_logbook` tag rather than the name. Expedition now reads entry
-13.0%, return -2.7%, spread +11.9% over 7 days, and sorts first on the page.

The logbook stays in the return basket too, holding ~15% of Expedition's supply
weight. Expeditions drop logbooks, so sustain is real return and excluding it
would understate the mechanic. The trade-off is that one item sits on both sides
of the card and damps the spread slightly (+11.9% against +12.1% held out); the
card says so outright.

Worth noting: `npm run build` passed while `resolveEntry` was missing from the
import list. A bundler treats an unimported identifier as a free variable, so it
only failed as a runtime ReferenceError once the tab was actually opened. Build
green is not evidence a module resolves.

## Pool movers were hiding each mechanic's best drops

Ritual's card headlined Omen of Putrefaction (0.5 ex, +561%), Refreshment
(0.7 ex) and Sinistral Necromancy (1.5 ex). Omen of Chance at 5,635 ex appeared
nowhere. Anyone scanning that card would conclude Ritual drops junk. Breach was
the same: sub-3-ex catalysts on show while Refined Sibilant Catalyst sat at
2,020 ex.

Structural, not bad luck — ranking by percentage always favours the cheapest
markets, because 0.07 → 0.47 ex is +561% and 5,300 → 5,635 ex is +6%. Adding
more rows would only have added more dust.

Three views per card now, all from one traversal (`poolContributions`):

- **Most valuable drops** — a plain price sort, so the chase items are visible.
  Ritual leads with Omen of Chance, then the Annulment and Erasure omens. Some
  clear once an hour, so cleared volume sits on every row and thin ones are
  tinted; the caveat is shown rather than the item hidden.
- **What moved the index** — ranked by contribution to the index move, which for
  a fixed-weight index decomposes exactly and **sums to the index change**.
  Breach: Refined Sibilant Catalyst +18.6pp of the +18.5% move. Ritual: Omen of
  Chance +2.97pp against Secret Compartments -1.07pp. The percentage stays
  alongside, so "Omen of Refreshment +241%, 0pp" reads as exactly what it is.
- **Show all N pool markets** — a sortable table of every market with price,
  volume, weight, change and contribution. Nothing is unreachable any more,
  which is the real fix; the shortlists are a summary, and a summary is what
  hid Omen of Chance.

The first attempt at contribution used weight × percentage change. That is not
additive in a price index — it summed to 38pp against a 2.88% move. The
exact-sum property is now the regression test, asserted to 1e-12.

Only the mover shortlists keep a liquidity gate. The other two views show
everything.
